## Addendum (11:30): first real test by Daniel, and what changed
Daniel tried it on the Mac. The mic and speech-to-text worked ("heard Jump up"), but there was no jump command, so Gemini picked the nearest thing (`play_trick`: a yawn/sniff) and the HUD text stayed on screen, which read as "stuck" and "spamming". Fixes (all tested):
- **New command `jump`** (8th; "jump / hop / leap"): the dog hops 70 px on the spot via `jumpTo`. Trace in the real page: y 532 -> 462 -> 532 over ~0.7 s.
- **Per-command descriptions for Gemini** (Daniel's idea, better than one function with an enum): each command is its own function with a description of what it is and which words mean it, plus `no_action`; `allowedFunctionNames` = all of them. Live: 15/15 sensible phrases ("bounce around" -> jump, "I love you" -> good_boy, "surprise me" -> play_trick, "play dead" -> lie_down, weather -> none).
- **`thinkingBudget: 0`** (the model otherwise "thinks" 1.8-2.9 s; now ~1.0-1.5 s, one 4.4 s outlier) and the timeout raised 4 s -> 6 s. `thinkingLevel: minimal` returns HTTP 400 on this model; do not use.
- **HUD voice text expires after 5 s** (it never cleared before).
- **Hold-to-talk button sent a stop on both pointerup and pointerleave**: now one stop per start.
- Dev aids: `ZOOMIES_LOG_RENDERER=1` prints the page console and the dog's events (`[dog] {...}`) in the terminal and exposes `window.__dog`.
- Mistake worth remembering: `pkill -f "zoomies-p1/app"` also killed my screenshot preview server on port 5198 (restart it from the scratchpad vite config); use `pkill -f "electron-vite dev"`.
